## 📌 О проекте

**Habit-Graph** — это full-stack веб-приложение для отслеживания ежедневных привычек и времени фокусировки с наглядной аналитикой. Вместо скучных списков задач сервис строит тепловые карты активности (Heatmaps) за год и месяц, рассчитывает динамику прогресса и позволяет фиксировать время через встроенный секундомер реального времени.

Главная цель проекта — продемонстрировать чистую, отказоустойчивую архитектуру серверного приложения на **Go** (Clean Architecture, работа с пулом соединений PostgreSQL без тяжелых ORM, сквозное кэширование в Redis с фоновыми ретраями и Graceful Shutdown) в связке с современным реактивным интерфейсом.

### ✨ Ключевые возможности
* **⏱️ Интерактивный секундомер реального времени:** запуск, пауза и завершение сессии с автоматическим округлением и отправкой времени на сервер. Состояние активного таймера синхронизируется с `localStorage`, защищая прогресс от случайного закрытия вкладки или перезагрузки страницы.
* **📅 Два масштаба тепловой карты (Месяц / Год):**
  * **Годовой граф (GitHub-style):** 52/53 недели активности с плавающими тултипами, подсветкой осей и мгновенным переходом к деталям выбранного дня.
  * **Месячный календарь:** детализированная сетка месяца с индивидуальными прогресс-барами для каждого дня.
* **📈 График динамики за месяц (Trend Chart):** кастомная SVG/Bar визуализация, отображающая распределение минут по дням, линию среднего темпа и пиковые дни продуктивности.
* **⚡ Накопительный учет (Upsert):** несколько сессий в течение одного дня автоматически суммируются на уровне СУБД (`ON CONFLICT DO UPDATE`), а кэш в Redis инвалидируется с механизмом фоновых повторных попыток.
* **🛠️ Скрытый режим ручного ввода:** удобный аккордеон для добавления или корректировки времени за прошедшие даты.

### Архитектура бэкенда (Clean Architecture)

Проект разделен на независимые слои с инверсией зависимостей через интерфейсы:

```text
Habit-Graph/
├── cmd/
│   └── main.go                        # Точка входа, инициализация пулов, DI и Graceful Shutdown
├── internal/
│   ├── core/                          # Ядро и переиспользуемые инфраструктурные пакеты
│   │   ├── domain/                    # Доменные модели (Habit, Track) и правила бизнес-валидации
│   │   ├── errors/                    # Кастомные типизированные ошибки (ErrorApp) и маппинг статус-кодов
│   │   ├── logger/                    # Конфигурация JSON-логгера log/slog
│   │   ├── repository/                # Инициализация подключений к pgxpool и Redis
│   │   └── transport/                 # HTTP-сервер с таймаутами, CORS middleware, JSON-хелперы
│   └── habits/                        # Доменный модуль привычек
│       ├── transportHTTP/             # HTTP-хендлеры, DTO и маппинг запросов/ответов
│       ├── service/                   # Бизнес-логика (Usecases), оркестрация БД и кэша, фоновые ретраи
│       └── repository/
│           ├── postgres/              # SQL-запросы (CRUD, аналитическая выборка графа, Upsert)
│           └── redis/                 # Хэш-хранилище графов, атомарные пайплайны и инвалидация по ключу/паттерну
├── migrations/                        # SQL-миграции (000001_init.up.sql / .down.sql)
├── frontend/                          # SPA-приложение на React + TypeScript + Vite
├── compose.yml                        # Оркестрация контейнеров (postgres, redis, migrate, api, frontend)
├── Dockerfile                         # Multi-stage сборка Go-бинарника в минимальный scratch-образ
└── Makefile                           # Автоматизация команд разработки и деплоя

```

#### Инженерные особенности реализации:

1. **Cache-Aside + Background Retries:** При запросе графика за год (`GetGraph`) сервис сначала обращается к Redis (`HGETALL`). В случае промаха данные забираются из PostgreSQL и асинхронно сохраняются в кэш на 24 часа через `context.WithoutCancel` и Redis Pipeline. При записи новой активности или удалении привычки кэш сбрасывается; если Redis временно недоступен, запускается горутина с 5 ретраями (интервал 2 сек) для предотвращения рассинхронизации данных.
2. **Атомарный Upsert в PostgreSQL:** Добавление времени за день использует составной первичный ключ `(habit_id, date)` и конструкцию `ON CONFLICT (habit_id, date) DO UPDATE SET duration_minutes = activities.duration_minutes + EXCLUDED.duration_minutes`, что гарантирует отсутствие гонок данных при параллельных запросах.
3. **Минимальный размер Docker-образа:** Бэкенд компилируется со статической линковкой (`CGO_ENABLED=0`) и флагами `-ldflags="-w -s"`, после чего копируется в чистый образ `FROM scratch` вместе с TLS-сертификатами и таймзонами.

## 🚀 Быстрый старт и запуск

### Предварительные требования

* Установленные **Docker** и **Docker Compose**
* Утилита **Make** (опционально, для удобного запуска команд)

### Пошаговый запуск в Docker

1. **Клонируйте репозиторий:**
```bash
git clone [https://github.com/N1ktarchik/habbit-graph.git](https://github.com/N1ktarchik/habbit-graph.git)
cd habbit-graph

```


2. **Проверьте конфигурацию окружения:**
В проекте уже присутствует `.env.example` (и рабочий `.env` для локального Docker-окружения). При необходимости скопируйте его:
```bash
cp .env.example .env

```


3. **Соберите и запустите все контейнеры:**
```bash
make docker-up
# или без make: docker compose up -d --build

```


*При запуске Docker Compose автоматически поднимет `postgres` и `redis`, дождется прохождения их `healthcheck`, выполнит миграции через контейнер `migrate`, после чего запустит `api` и `frontend`.*
4. **Откройте приложение в браузере:**
* 🌐 **Веб-интерфейс (Frontend):** [http://localhost:3000](http://localhost:3000)
* ⚙️ **Backend REST API:** [http://localhost:8080](http://localhost:8080)
* 🐘 **PostgreSQL (внешний порт):** `localhost:5433` (БД: `habit-graph_app`, юзер: `postgres`)
* 🟥 **Redis (внешний порт):** `localhost:6379`

### 🧰 Команды Makefile

В проекте настроен `Makefile` для управления жизненным циклом приложения и базы данных:

| Команда | Описание |
| --- | --- |
| `make help` | Показать список всех доступных команд с описанием |
| `make docker-up` | Собрать образы и запустить все сервисы в фоновом режиме (`docker compose up -d --build`) |
| `make docker-down` | Остановить и удалить контейнеры проекта |
| `make docker-logs` | Просмотр live-логов всех контейнеров (`docker compose logs -f`) |
| `make migrate-up` | Применить все актуальные миграции к базе данных |
| `make migrate-down` | Откатить последнюю примененную миграцию на 1 шаг назад |
| `make migrate-create NAME=...` | Создать новую пару SQL-миграций в папке `./migrations` |
| `make db-reset` | **Полная очистка БД:** удаляет Docker-тома (`down -v`), поднимает стек заново и накатывает миграции |
| `make run-back` | Локальный запуск Go-сервера без Docker (`go run ./cmd/main.go`) |
| `make run-front` | Локальный запуск Vite dev-сервера на порту `3000` |

## 📡 Документация REST API

Все запросы и ответы используют формат `application/json`. Валидация входных данных (длина названия от 3 до 120 символов, описание до 200 символов, корректность UUID, проверка года `>= 2026` и даты) выполняется на уровне домена и транспортного слоя.

> **Примечание:** В текущей версии сервис работает без привязки к сессиям/авторизации для мгновенного локального развертывания и тестирования основного функционала.

### Сводная таблица эндпоинтов

| Метод | Эндпоинт | Описание | Тело запроса (JSON) | Код и формат ответа |
| --- | --- | --- | --- | --- |
| `POST` | `/api/habits` | Создать новую привычку | `{"title": "Чтение", "description": "Техническая литература"}` | `201 Created`<br>

<br>`HabitResponseDTO` |
| `GET` | `/api/habits` | Получить список всех привычек | — | `200 OK`<br>

<br>`[]HabitResponseDTO` |
| `PATCH` | `/api/habits/{id}` | Частично обновить название и/или описание привычки | `{"title": "Новое имя", "description": "..."}` | `200 OK`<br>

<br>`HabitResponseDTO` |
| `DELETE` | `/api/habits/{id}` | Удалить привычку (каскадно удаляет историю и очищает кэш Redis) | — | `204 No Content` |
| `POST` | `/api/habits/{id}/activities`<br>

<br>*(алиас: `/api/habits/{id}/track`)* | Записать / прибавить время активности за конкретную дату | `{"date": "2026-10-24", "value": 45}` *(время в минутах)* | `200 OK`<br>

<br>`{"status": "ok"}` |
| `GET` | `/api/habits/{id}/graph?year=2026` | Получить карту активности за указанный год (из кэша Redis или БД) | — | `200 OK`<br>

<br>`{"2026-10-24": 45, "2026-10-25": 90}` |
